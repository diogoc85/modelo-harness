# Delivery model profiles

Select one profile before planning implementation. Classification chooses requirements; it does not
authorize implementation.

| Profile | Primary value | Typical operator | Commercial signal |
|---|---|---|---|
| Traditional | Features or an internal workflow | A person uses the software | Project, license or none |
| SaaS | Ongoing access to hosted capabilities | Customer users operate the product | Subscription, seat or usage |
| Service as Software | A completed work outcome | Software agents perform the work | Task, consumption or outcome |
| Hybrid | Hosted product plus agent-delivered outcomes | Users supervise agents through a product | Subscription plus usage/outcome |

Use the model explicitly declared in the PRD when its behavior supports that declaration. Otherwise
classify from the value delivered, who performs the work, tenancy and how success is measured. Ask
for confirmation when the difference would change data isolation, billing, autonomy or risk.

AI-assisted features alone do not make a product Service as Software. The defining signal is that
the software owns a bounded service workflow and is accountable for a verifiable outcome.
