# Tasks

Place approved work in `current/` and completed records in `completed/`. Each task should reference
the PRD, define dependencies, acceptance criteria, security considerations and verification commands.

Use `docs/tasks/TEMPLATE.md` for multi-step, dependent or materially risky work. Keep simple,
localized changes lightweight. Move a task record to `completed/` only after its acceptance criteria
and required verification have been checked against fresh evidence.

Plans are execution aids, not new product specifications. Link requirements to the governing PRD,
profile or ADR instead of copying them without provenance.
